# Fase 8 — IA generativa

Diseñar una página a partir de una descripción y refactorizar una página existente con una instrucción, siempre con vista previa y como **un único cambio que se puede deshacer**.

## Uso

| Menú **IA** | Qué hace |
|---|---|
| Generar página con IA… (Ctrl+G) | Petición en lenguaje natural → página nueva (o sustituye la actual). Vista previa, YAML y avisos antes de **Aplicar**; **Regenerar** pide otra versión. |
| Refactorizar página con IA… (Ctrl+Shift+G) | Instrucción sobre la página actual → página modificada, con la pestaña **Cambios** (diff del YAML). |
| Extraer estilos repetidos | Propiedades de estilo idénticas en 3 o más widgets del mismo tipo → un `style_definitions` aplicado a todos. El aspecto no cambia. |
| Ids descriptivos | `btn_3`, `lbl_12`… → `btn_salon`, `lbl_temperatura` según su texto, actualizando acciones, `textarea`, `id(...)` en lambdas y YAML libre. |
| Configurar IA… | Proveedor, modelo, clave y URL; botón **Probar la conexión**. |

## Proveedores

| Proveedor | Necesita | Notas |
|---|---|---|
| Generador local | nada | Plantillas para peticiones de domótica: luces, persianas, clima/termostato, energía, música, escenas, ajustes, tiempo, alarma, reloj, barra de navegación, «N botones». Entiende números («seis luces»), entidades (`light.salon`), tema claro/oscuro y colores. Refactoriza: tema oscuro/claro, textos más grandes, redondear, color de los botones, estilos, ids. |
| Claude (Anthropic) | clave de console.anthropic.com o `ANTHROPIC_API_KEY` | Modelo por defecto `claude-sonnet-5-5` (se puede cambiar). |
| Compatible con OpenAI | URL y modelo; clave opcional | OpenAI, LM Studio (`http://localhost:1234/v1`), Ollama (`http://localhost:11434/v1`), llama.cpp… Con un modelo local nada sale del equipo. |

**Privacidad**: sólo se envía el YAML de LVGL de la página (al refactorizar), el tamaño de la pantalla y los nombres de páginas, estilos, fuentes y colores. Nunca el resto del YAML del dispositivo (Wi-Fi, `secrets`, claves de API). La clave se guarda en la base de datos de ajustes local (`%APPDATA%\OpenLVGLStudio`); las variables de entorno tienen prioridad si el campo está vacío.

## Cómo funciona

```
petición ─► prompt (reglas ESPHome LVGL + catálogo + pantalla + contexto)
        ─► proveedor ─► extraer bloque ```yaml (normalizado a lvgl: pages:)
        ─► importador de ESPHome (el mismo que para tus YAML)
        ─► validación: tipos del catálogo, dentro de la pantalla, fuentes, avisos del importador
             └─ problemas → se devuelven al modelo para que corrija (hasta 2 veces más)
        ─► integración: ids únicos (renombrando también sus referencias), estilos y fuentes nuevos
        ─► vista previa ─► Aplicar = ReplaceProjectData (Ctrl+Z)
```

- `olvgl/application/ai.py`: proveedores, prompt, `extract_yaml`, validación y bucle de corrección (`AIDesigner.generate/refactor`), `merge_pages`, generador local.
- `olvgl/domain/refactor.py`: `extract_styles`, `descriptive_ids`, `rename_references` (sin IA, deterministas).
- `olvgl/presentation/ai_ui.py`: diálogos (la petición va en un hilo aparte; la ventana no se bloquea).
- Al refactorizar, si un id desaparece de la página pero otra página lo sigue usando, se avisa.

## Línea de órdenes

```
python -m olvgl.cli generate "energía solar y consumo con la hora" --display 800x480 --out energia.yaml
python -m olvgl.cli generate "página de clima" --into panel.yaml --provider anthropic
python -m olvgl.cli generate "luces" --provider openai --base-url http://localhost:11434/v1 --model qwen2.5-coder:14b
```

Devuelve JSON con las páginas, intentos y avisos; el YAML es un fragmento `lvgl: pages:` para pegar en tu configuración. El servidor (`serve`) admite `{"cmd": "generate", "prompt": …}`.
